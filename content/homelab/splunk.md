# Splunk
display_title: My Splunk Home Lab
skills: Splunk installation and setup, SPL basic searching, index creation and management, log ingestion, source type configuration, Splunk architecture (forwarder, indexer, search head), Linux SSH authentication log analysis
tools: Splunk Enterprise, Windows, OpenSSH logs

<p><strong>My Splunk Home Lab</strong></p><p>I am learning to work as a SOC analyst, and Splunk is one of the main tools SOC teams use to watch logs and catch attacks. Reading about it wasn't enough for me, so I installed it on my own laptop to learn it hands-on.</p><p>In this lab :</p><ul><li>installed Splunk Enterprise on Windows</li><li>practiced searching using Splunk's own logs</li><li>created an index and loaded real SSH login logs from a Linux server into it</li></ul><p>This is the first part of my brute force detection project. The logs are full of failed SSH logins, and next I will use Splunk to find where the attack is coming from and build an alert for it.</p><p>I wrote these notes in my own words so I can come back and revise them anytime. I am planning on extending this lab as I learn through different things in splunk. </p><p><strong>What is Splunk</strong></p><ul><li>Splunk is a platform that lets me collect logs, store them, organise them and search through them</li><li>The way I think about it: it's like Google, but for logs. Instead of opening log files one by one, I put everything into Splunk and search it</li></ul><p><strong>The 3 main parts</strong></p><ul><li><strong>Forwarder</strong> <ul><li>Sits on the machine that creates the logs and sends them to Splunk</li><li>I think of it as the delivery person</li></ul></li><li><strong>Indexer</strong> <ul><li>Receives the logs, splits them into events, records the time of each event and stores them</li><li>I think of it as the storage room</li></ul></li><li><strong>Search Head</strong> <ul><li>The web page where I type my searches</li><li>I think of it as the front desk</li></ul></li></ul><p>In my lab all 3 run inside the same Splunk install on my laptop. I am uploading the log file from my computer, so I am not installing a forwarder this time.</p><p><strong>Fields every event gets by default</strong></p><ul><li>_time: when the event happened</li><li>host: which machine it came from</li><li>source: which file it came from (the path)</li><li>sourcetype: what kind of log it is (Windows log, syslog, web log)</li><li>index: which storage bucket it went into</li></ul><p>I noticed these are the easiest way to narrow down a search, so I try to start my searches with index= and sourcetype=.</p><p><strong>Installing Splunk</strong></p><p>I went with <strong>Splunk Enterprise 10.6.1.1</strong> on the free trial. It gives me 60 days and up to 500 MB of data a day, which is more than enough for a home lab.</p><p>I signed up for the trial, downloaded the Windows .msi installer, ran the setup, created my admin username and password, and then opened Splunk in my browser.</p><p><img src="media/splunk-1.png" /><strong> </strong></p><p><img src="media/splunk-2.png" /></p><p><img src="media/splunk-3.png" /></p><p>Then I logged in with the credentials that I created initially.</p><p><img src="media/splunk-4.png" /></p><p><strong>Looking at Splunk's own logs first</strong></p><p>Before adding my own data, I wanted to get comfortable searching.</p><ul><li>Splunk stores everything in buckets called <strong>indexes</strong></li><li>Splunk also logs its own activity into an index called _internal. Indexes that start with _ belong to Splunk itself</li><li>This felt like a safe place to practise because it always has data</li></ul><p>So in <strong>Search &amp; Reporting</strong> I ran:</p><p>index=_internal</p><ul><li>I set the time picker on the right to the last 5 minutes. I learned that every search is filtered by time, so the time picker decides what I see</li><li>Then I filtered by sourcetype to see only Splunk's own logs. These came from 4 different places (log files like splunkd.log and metrics.log)</li></ul><p><strong><img src="media/splunk-5.png" /></strong></p><p><strong>Loading my own log file</strong></p><p><strong>The log file I used</strong></p><p>I am using OpenSSH_2k.log. It has 2,000 lines of real SSH login activity from a Linux server called LabSZ, taken from the public Loghub dataset. It has lots of Failed password lines, which is exactly what a brute force attack looks like, so it's perfect for my project.</p><p><strong>Step 1: I created an index</strong></p><p>I needed a bucket to store this data, so I created an index called bruteforce_openssh. I kept it separate so my lab data doesn't mix with anything else, my searches stay fast, and I can delete it later without breaking anything.</p><p><strong><img src="media/splunk-6.png" /></strong></p><p><strong>Step 2: I added the file</strong></p><p>I went to <strong>Settings -&gt; Add data -&gt; Browse</strong> and picked the log file from my laptop.</p><p><img src="media/splunk-7.png" /></p><p><strong>Step 3: I picked the source type</strong></p><p>I selected linux_secure because I am working with Linux authentication logs. The source type tells Splunk how to read the log, like where the timestamp is and how to pull out the user and IP. If I pick the wrong one, the data comes in messy and hard to search.</p><p><img src="media/splunk-8.png" /></p><p><strong>Step 4: Input settings</strong></p><ul><li><strong>Host</strong>: the name of the original machine. As the downloaded logs is from LabSZ, I sticked to the same</li><li><strong>Index</strong>: where the data goes. I chose my bruteforce_openssh index</li></ul><p><img src="media/splunk-9.png" /></p><p><strong>Step 5: I reviewed and submitted</strong></p><p>Before submitting, I checked everything on the review page:</p><p><img src="media/splunk-10.png" /></p><p><strong>Checking that it worked</strong></p><p>I searched my new index:</p><p>index=bruteforce_openssh</p><p>I have to remember to set the time picker to <strong>All time</strong>. These logs are old, so if I search the last 24 hours I get nothing, even though the upload worked.</p><p><strong><img src="media/splunk-11.png" /></strong></p>
